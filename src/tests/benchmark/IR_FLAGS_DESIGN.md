# Flag values in mixed IR

Policy 10 extends policy 9 with unconditional ARM data-processing flags. ADD,
ADC, SUB, RSB, SBC and RSC produce explicit N/Z/C/V graph values. Logical
operations produce N/Z and shifter carry while preserving V. TST/TEQ/CMP/CMN
update flags without a register result. SBC/RSC without S also join this path.
Immediate operands and immediate register shifts include the ARM zero-shift
rules and RRX. Register-controlled shifts, conditional instructions, branches,
SPSR restoration and flag-setting multiplies remain with the original emitter.

Flags are ordinary snapshot consumers, so intermediate flags needed by a failed
memory guard remain live, even when a later instruction overwrites them. Pure
values needed only at that exit use the existing memoized cold reconstruction.
Input carry is captured before writing the new flags. Snapshot lowering still
consumes all sources before assigning architectural destinations.

The old policies do not enable this decoder extension. Policy 9's two captured
busy-loop modules remain byte-identical. Public mode 10 uses a shared strict
parser; it must never be interpreted as single-character mode 1. Existing
compile-time capability gates also apply.

The independent interpreter matrix varies all 16 data-processing opcodes,
16 operand forms, boundary inputs, incoming flags, every prefix budget, and
successful/failed mappings. It includes source/destination overlap and carry
consumers. A separate production-runner fixture places ADDS/ADCS before a
faulting access and another ADDS after it, checking callback-visible state,
retry, stop, writes and final progress against native.

This is an opt-in experiment. Full tests, explicit rebuilt fault probes, exact
native replay and controlled gameplay comparisons are required before any
promotion. Joining more instructions or changing generated byte counts alone
does not establish a speedup.
